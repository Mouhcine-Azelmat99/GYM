# English and Arabic

The language selector is available on sign-in, invitation, password-reset, and authenticated pages. It changes the current screen without reloading or clearing forms. A browser preference is saved as `forma.language.v1`; on the first visit, Arabic browser languages use Arabic and other languages use English. Storage-disabled browsers can still switch for the current visit.

React components use `useTranslation()` from react-i18next. `src/i18n.js` configures the two languages, English fallback, document `lang`/`dir`, title, plural rules, and interpolation. `src/locales/ar.js` contains Arabic messages; literal English sentences are translation keys. Keep complete sentences together with named interpolation values. Do not concatenate translated sentence fragments. Arabic counts have zero, one, two, few, many, and other forms.

`date()` and `money()` in `src/api.js`, and `locale()` and `number()` in `src/i18n.js`, format displayed values. Arabic uses Latin digits (0?9) and the Gregorian calendar. Internal identifiers, API enum values, currency codes, ISO dates, timezone calculations, QR payloads, and numeric form values remain language-independent. CSV exports include a UTF-8 BOM for Arabic column headings.

RTL is set on the document. Styles use logical inline spacing, borders, alignment, and drawer placement. Arabic uses locally served Noto Sans Arabic; English uses Inter. Navigation arrows mirror; photographs, video, and QR codes do not. Mixed-direction names are isolated with `bdi`, and interpolation isolates embedded values. Email, phone, URL, numeric, and date inputs retain their appropriate input direction.

New notification events store language-independent message keys and snapshot values, so changing languages never changes historical event details. Older stored messages without translation metadata retain their original text. Gym-entered names, plan descriptions, session titles, and room names are displayed as entered. Outgoing Brevo email templates continue to use English; the language preference is local to the browser, not an account-level email preference.

Validation: `npm run test` covers preference persistence and blocked storage, document direction, Arabic plural categories, formatting, English fallback, and notification snapshots. `npm run build` validates the production bundles. Browser checks cover Arabic staff pages, mobile member screens, drawer direction, switching back to English, and preserved form option values.

Implementation references: [react-i18next hooks](https://react.i18next.com/latest/using-with-hooks), [i18next plurals](https://www.i18next.com/translation-function/plurals), and [language fallback](https://www.i18next.com/principles/fallback).
